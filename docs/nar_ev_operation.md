# 地方競馬 EV-first 運用設計

目的は的中数ではなく、検証済み期待値の最大化です。購入対象は「自前確率が市場確率を上回り、かつその差が手数料・締切直前のオッズ変動・モデル誤差を吸収できる馬券」に限定します。

## まず使う馬券

最初は単勝・複勝のみを対象にします。

- 単勝: 確率校正と期待値の検証が最も簡単。
- 複勝: 地方の小頭数・人気集中レースで歪みが出やすいが、控除と払戻レンジを必ず考慮する。
- 馬連・ワイド・三連系: 独立仮定が崩れやすく、組み合わせ数が増えて過剰購入になりやすい。単勝モデルの校正が十分に確認できるまで紙運用。

## データ優先順位

有料データを使う価値がある順に並べます。

1. 過去レース結果、出走表、馬柱
2. レース当日の馬体重、騎手変更、取消、馬場状態
3. 時系列オッズ、少なくとも購入予定時刻と締切直前
4. 調教、厩舎コメント、指数、映像由来メモ
5. 予想印、SNS、新聞評価などの市場人気に近い情報

最重要は「ライブで使える時刻」と「バックテストで使う時刻」を一致させることです。締切後にしか分からない情報や最終オッズを特徴量に混ぜると、期待値が過大評価されます。

## 推奨データ源

現実的には次の組み合わせから始めます。

- 無料公式: 地方競馬情報サイトの出馬表、結果、オッズ、データ検索。
- 投票サイト: SPAT4、楽天競馬、オッズパークの表示情報。利用規約と自動取得可否を必ず確認。
- 有料候補: netkeiba、競馬ブック、競馬道などの地方競馬対応データ、指数、馬柱。CSV/API提供があるものを優先。
- 手入力補助: 有料指数や新聞印がCSVで取れない場合は、まず1場1日だけ手入力して予測改善を検証する。

購入判断は「便利そう」ではなく、追加したデータで時系列バックテストの logloss、Brier score、校正、期待利益、CLV が改善するかで決めます。

## モデル方針

ベースラインは市場オッズから控除を除いた no-vig 確率です。これを超えられない独自モデルは購入に使いません。

推奨する段階:

1. 市場ベースラインのみ: 購入なしが正常。
2. レース条件 + 馬の近走 + 騎手/調教師 + 枠 + 距離/馬場適性。
3. 競馬場別モデル: 大井、船橋、川崎、浦和、門別などは性質が違うため分けて検証。
4. オッズ併用モデル: 直前オッズを特徴量に入れる場合、運用で取得できる時刻に固定する。
5. アンサンブル: 市場確率と独自モデルをブレンドし、過信を抑える。

出力確率は必ず校正します。勝率10%と出した馬が長期で本当に約10%勝つかを、オッズ帯・人気順・競馬場・距離・馬場ごとに確認します。

## 購入ルール

`src/generate_bets.py` の考え方を地方競馬にもそのまま使います。

- `ev_per_yen = probability * odds - 1`
- 原則 `ev_per_yen >= 0.05` 以上のみ検討。
- 小頭数・低オッズ・締切直前に下がりやすい馬は、閾値を `0.08` から `0.12` へ上げる。
- 資金配分は 0.25 Kelly 以下。
- 1点上限は資金の 1% から 3%。
- 1レースの合計上限も別途設定する。目安は資金の 5% 以下。
- 同じレースで相関の高い買い目を大量に買わない。

実購入前は最低30日、できれば300点以上を紙運用し、期待利益と実損益とCLVを比較します。

## 日次フロー

1. 当日開催の出馬表を取得する。
2. 取消、騎手変更、馬体重、馬場状態を更新する。
3. 予測確率を作成する。
4. 購入予定時刻のオッズを取得する。
5. `src/generate_bets.py` と同じ形式で BUY/PASS を出す。
6. 実購入または紙購入ログを `data/bet_log.csv` に残す。
7. 確定結果、払戻、締切直前オッズを追記する。
8. バックテストと校正レポートを更新する。

## 追跡指標

- Expected ROI
- Actual ROI
- CLV: 購入オッズ / 締切オッズ
- Brier score
- Log loss
- calibration slope/intercept
- オッズ帯別 ROI
- 人気順別 ROI
- 競馬場別 ROI
- 最大ドローダウン

Actual ROI より CLV と校正を重視します。短期の的中/不的中はノイズが大きいため、買い目の良し悪しは「締切より良い価格で買えているか」と「確率が校正されているか」で判定します。

## 有料データ購入の基準

月額データは次を満たす場合だけ継続します。

- 運用時刻で取得できる。
- CSV、API、または安定したエクスポートがある。
- 利用規約上、個人分析・保存・自動処理に問題がない。
- 導入前後のバックテストで市場ベースラインを上回る。
- データ費を控除した月次期待利益がプラス。

高額データは一括契約せず、まず1か月または1場だけで検証します。

## 直近の実装タスク

1. `data/nar_exports/` を作り、地方競馬用の `races.csv`、`starts.csv`、`odds_snapshots.csv`、`results.csv` に正規化する。
2. 地方競馬の `race_id` 体系を定義する。
3. 単勝だけの学習データを作る。
4. 市場 no-vig ベースラインと独自モデルの比較レポートを作る。
5. 紙購入ログに CLV と確定払戻を記録する。
6. 300点以上の紙運用で、BUY条件と資金配分を調整する。
